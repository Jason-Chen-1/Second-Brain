# API-Bank Tool-Augmented LLM Benchmark

## Core Definition

API-Bank is a benchmark and training resource for evaluating and improving tool-augmented large language models across API calling, API retrieval, and multi-step API planning [S04].

Li et al.'s API-Bank paper defines three tool-use abilities: Call, where APIs are known and the model must call the right one; Retrieve+Call, where APIs are unknown and the model must retrieve then call one API; and Plan+Retrieve+Call, where the model must repeatedly plan, retrieve, and call multiple APIs when APIs are unknown [S04].

## Key Claims

- API-Bank's design principles were derived from interviews with over 500 users interested in adding tools to LLMs, and the authors identify two user-requirement dimensions: few versus many APIs in a pool, and single versus several API calls per turn [S04].
- The benchmark construction standards emphasize domain diversity, API authenticity, API diversity, and evaluation authenticity through a functional system that executes model-proposed API calls and evaluates their effect [S04].
- The evaluation system implements 73 APIs, including daily-use APIs such as weather forecast and APIs that access other AI models such as text-to-image generation [S04].
- API-Bank's manually annotated evaluation set retains 314 dialogues with 753 API calls after discarding 21.5% of 400 annotated dialogues because of annotation issues [S04].
- The paper reports an average manual annotation cost of $8 per dialogue and says the 73 APIs required 98 person-days of senior research and development engineering time to implement [S04].
- For Retrieval+Call and Plan+Retrieval+Call, API-Bank provides a special `APISearch` tool that retrieves potentially relevant API metadata by comparing sentence embeddings from query keywords and API meta-information [S04].
- API-call correctness is evaluated with accuracy based on consistency between predicted and annotated API calls, including whether the same database queries or modifications are performed and whether returned results match; response quality is evaluated with ROUGE-L [S04].
- The training set is generated by a Multi-agent method with five LLM agents that generate domains, APIs, user queries, API calls and responses, and quality checks; the paper reports this reduces cost by 98% compared with manual annotation [S04].
- API-Bank's training set has 1,000 domains, 2,138 APIs, 1,888 dialogues, 5,221 turns, 3,147 single-call instances, and 493 multiple-call instances [S04].
- API-Bank's evaluation set has 8 domains, 73 APIs, 314 dialogues, 914 turns, 363 single-call instances, and 122 multiple-call instances [S04].
- In the API-Bank evaluation, GPT-4 reports 60.24% total API-call correctness and 0.3910 ROUGE-L, while GPT-3.5-turbo reports 47.16% correctness and 0.4267 ROUGE-L [S04].
- Lynx-7B, fine-tuned from Alpaca-7B on API-Bank's training set, reports 39.58% total correctness and 0.3794 ROUGE-L, compared with Alpaca-7B at 15.19% correctness and 0.0318 ROUGE-L [S04].
- The paper reports that GPT-4 excels in the Plan+Retrieve+Call setting with 70.00% correctness, compared with 22.00% for GPT-3.5-turbo and 20.00% for Lynx-7B [S04].
- Error analysis reports that Alpaca's largest error category is `No API Call` at 36.77%, Lynx's largest error category is `API Hallucination` at 61.38%, and GPT-4's largest error category is `Failed API Retrieval` at 67.86% [S04].

## Evidence and Sources

S04 is a high-quality public paper/PDF in the manifest, dated 2023-12, and published in the EMNLP 2023 proceedings pages 3102-3116 according to the PDF text [S04].

The paper compares API-Bank with DATESET, APIBench, ToolAlpaca, ToolBench variants, and ToolQA, and claims API-Bank is broader because it includes multi-turn and multi-call dialogues, API-call and response evaluation, and all three abilities: Call, Retrieve, and Plan [S04].

The authors fine-tune Lynx from LLaMA-7B via Alpaca-7B initialization for three epochs with batch size 256 and learning rate `2e-5` [S04].

## Limitations and Counter-Evidence

API-Bank focuses only on English, and the authors state that data construction and model evaluation for other languages are future work [S04].

The paper only reports fine-tuning Lynx-7B on API-Bank and does not explore larger-scale open models in the reported experiments [S04].

The authors state that they trained a larger commercial tool-augmented LLM internally but cannot report or analyze its results for anonymity reasons [S04].

The reported evaluation uses a zero-shot API-call prompt format, and the paper attributes some false API-call-format errors to models relying only on instruction-based guidance for the required API-call format [S04].

The paper's error analysis indicates that both fine-tuned and frontier models still face major tool-use failures: Lynx often hallucinates API names, while GPT-4 often fails API retrieval [S04].

Synthesis: API-Bank evaluates API calling, API retrieval, and multi-step API planning over executable API tasks, while [[tau-bench-agent-consistency-benchmark|Tau-Bench]] evaluates longer tool-agent-user conversations against final database state and repeated-trial `pass^k` reliability [S04] [S05].

Synthesis: ToolSandbox positions API-Bank as less stateful than ToolSandbox because API-Bank evaluates executable API-use dialogues but does not focus on implicit state dependencies between mutable tools [S04] [S06].
